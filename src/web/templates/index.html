Backtest

No rules are set for this strategy, so there is nothing to backtest yet — add at least one enabled BUY or SELL rule in the Rules panel and save it, then run the backtest.

How it works?

  1. Configure the instrument — pick the symbol, bar size and historical period in Strategy Configuration and press 💾 Save. If no data exists yet, download it from the “Download historical data” panel.
  2. Define the logic — in the Rules panel add + Buy / + Sell conditions on the price or indicators (SMA, RSI, …) and press 💾 Save. Rules reference features that must be enabled in Strategy Configuration.
  3. Preview signals — the Strategy Signals section in the strategy header shows when the latest bar fires BUY/SELL under the saved rules.
  4. Run the backtest — press ▶ Run backtest. It replays the saved rules over the whole dataset with next-bar fills, slippage and commission.
  5. Check the Gate — the report must pass every Gate threshold (Sharpe, max drawdown, win rate, worst week). If it fails, tweak the rules or feature config, save, and run again — iterate until the strategy passes on data it has not overfit.

The backtest always uses the saved rules/config — save before running.

Account Settings

Settings for your trading account — the broker it trades through (Trading Account), where its data and backtest results are stored, and the backtest costs. They apply to every strategy and live in data/account/account.json; a strategy's own values override them. Data folder is the single folder on this computer that holds the historical/ and backtest_results/ subfolders. Cloud storage and state persistence are not here: they are infrastructure, not account settings, and will be configured in .env when they are built. Secrets (*_PASSWORD, *_API_KEY…) are masked — leave the field empty to keep the existing value.
