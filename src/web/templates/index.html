No rules are set for this strategy, so there is nothing to backtest yet — add at least one enabled BUY or SELL rule in the Rules panel and save it, then run the backtest.

How it works?

  1. Configure the instrument — pick the symbol, historical period and bar size in Strategy Configuration and press 💾 Save. If no data exists yet, download it from the “Download historical data” panel.
  2. Define the logic — in the Rules panel add + Buy / + Sell conditions on the price or indicators (SMA, RSI, …) and press 💾 Save. Rules reference features that must be enabled in Strategy Configuration.
  3. Preview signals — the Strategy Signals section in the strategy header shows when the latest bar fires BUY/SELL under the saved rules.
  4. Run the backtest — press ▶ Run backtest. It replays the saved rules over the whole dataset with next-bar fills, slippage and commission.
  5. Check the Gate — the report must pass every Gate threshold (Sharpe, max drawdown, win rate, worst week). If it fails, tweak the rules or feature config, save, and run again — iterate until the strategy passes on data it has not overfit.

The backtest always uses the saved rules/config — save before running.

Strategy Configuration

Per-strategy settings for the active strategy (instrument, features, model thresholds). 💾 Save records them in this strategy's config object in the JSON file; switching strategy reloads the whole dashboard in that strategy's context. Risk limits live in the Risk Management panel below.

Rules

Rule-based conditions for the active strategy (consumed by the future simple_model). Stored with the strategy in strategies/active.json. Each rule fires when its conditions hold; a condition compares a feature to a number or to another feature.

Risk Management

Every signal passes through these limits before an order is placed, and the backtest replays the same rules so the Gate describes the system that will actually trade. Stored with the strategy.

Infrastructure / global defaults written to .env on disk. Most global settings apply on the next bot restart. Secrets (*_PASSWORD, *_API_KEY…) are masked — leave the field empty to keep the existing value.
